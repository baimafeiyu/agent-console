备注 / 踩坑速查

发票必须逐张上传，且上传后要等「采集」完成
一次传多张，系统只登记 1 张 —— 脚本已改成逐张。上传后系统要 OCR+查验，未完成时点「下一步」会被拒：「存在采集中、待人工确认或异常的发票，不允许报销！」；脚本会重试最多 6 分钟，仍失败请到「发票管理 → 待报销票据」处理。
删掉草稿 ≠ 释放发票
删掉已保存的草稿后再跑，向导树显示 4 份但单据里没有发票（价税合计 0）。必须到「待报销票据」把这批票据本身删掉。判据：上传时不再出现「已存在」才算干净。
分摊部门默认是「经办人」的部门
与出差人无关。规则：出差人所在部门 / 多人取职级最高者 / 同级取收款人部门。填了「分摊部门」会联动改「资金使用部门」。
rowKey 不唯一 / 命中 0 行
往返两程会生成 2 行、两行部门名相同 → 必须用数据字段定位（如 vstartplace=台州市）；匹配串同时支持「字段=值」与裸文本。命中不了时脚本会把每个数据行的字段写进 dump-S7-rows.json。
失败后怎么继续 / 为什么"删了还被拒"
退出码 10=重新登录；20=某步断言失败（先人工确认系统里有没有半成品草稿）。重复建单默认不再拦截：本机 run.json 里记过单据号时也只告警照跑（它读的是本机证据，不是 OA，所以你在 OA 删了草稿它不知道）——历史单据号会写进证据留痕；要拦就选「严格模式」。
不想碰发票池的探测法
把「发票上传方式」设为我手工传发票、附件不含发票 → 生成一版探测工单，跑到 S7（不会保存、也不碰发票池），用它定 rowKey、验填写。
